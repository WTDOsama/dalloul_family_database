# قاعدة بيانات أيتام عائلة دلول — النسخة الإلكترونية الكاملة 🕊️

نظام إدارة بيانات الأيتام والأسر — **تطبيق ويب متكامل يعمل عبر الإنترنت** بقاعدة بيانات PostgreSQL حقيقية (Supabase) ومصادقة آمنة وصلاحيات لكل مستخدم، جاهز للنشر على Vercel.

> تم الحفاظ على **نفس الواجهة العربية** والتصميم والقوائم والنماذج من النسخة الأصلية — التغيير الجوهري أن البيانات أصبحت في قاعدة بيانات آمنة على الإنترنت بدل التخزين المحلي في المتصفح.

## ✨ المزايا

| الميزة | الوصف |
|---|---|
| 🔐 مصادقة حقيقية | تسجيل دخول بالبريد الإلكتروني عبر Supabase Auth — لا كلمات مرور مخزنة في التطبيق |
| 👤 أول مدير آمن | شاشة إعداد تظهر **مرة واحدة فقط** عند أول تشغيل — لا يوجد حساب admin/admin123 مبرمج |
| 🛡️ صلاحيات حقيقية | مدير / موظف / مشاهد — مفروضة **على مستوى قاعدة البيانات (RLS)** وليس بإخفاء الأزرار فقط |
| 🗄️ قاعدة بيانات أونلاين | PostgreSQL مع مفاتيح أجنبية وقيود ومنع التكرار وترقيم تلقائي |
| 🔄 مزامنة فورية | أي إضافة أو تعديل من مستخدم تظهر عند بقية المستخدمين تلقائياً (Realtime) |
| 📜 سجل نشاط | توثيق تلقائي لكل عملية (إضافة/تعديل/حذف/دخول/خروج/إدارة مستخدمين) على مستوى قاعدة البيانات |
| 🔍 بحث وفلترة خادمية | البحث بالاسم ورقم الملف والهوية والأسرة والجوال والمنطقة — مع ترقيم صفحات |
| 📊 إحصاءات حية | كل الأرقام محسوبة من قاعدة البيانات (لا أرقام وهمية) |
| 📱 رموز QR آمنة | تحتوي معرّفاً داخلياً فقط — بدون هوية أو جوال أو أي بيانات حساسة |
| 📥 تقارير CSV/PDF | مع حماية من حقن المعادلات في Excel |
| 📱 متجاوب | يعمل على الحاسوب واللوحي وأندرويد وآيفون بنفس تصميم النسخة الأصلية |

## 🏗️ المعمارية التقنية

```
┌─────────────────────────────────────────────────────┐
│                    Vercel (HTTPS)                    │
│                                                     │
│  ┌──────────────────┐    ┌───────────────────────┐  │
│  │  الواجهة (Vite)   │    │  دوال الخادم (API)     │  │
│  │  index.html       │    │  /api/admin/users     │  │
│  │  نفس الواجهة العربية │    │  /api/admin/reset-…   │  │
│  │  + supabase-js    │    │  /api/health          │  │
│  │  (مفتاح عام فقط)   │    │  (مفتاح الخدمة السري   │  │
│  └────────┬─────────┘    │   في الخادم فقط) ✓     │  │
│           │               └───────────┬───────────┘  │
└───────────┼───────────────────────────┼──────────────┘
            │  (HTTPS + RLS)            │ (service role)
            ▼                           ▼
┌─────────────────────────────────────────────────────┐
│                  Supabase PostgreSQL                 │
│  profiles / families / orphans / assistance /        │
│  follow_ups / activity_logs                          │
│  + Supabase Auth + Row Level Security + Realtime     │
└─────────────────────────────────────────────────────┘
```

- **الواجهة**: نفس ملف HTML الأصلي (مع تعديلات الربط فقط) + وحدات JavaScript حديثة، تبنيها Vite.
- **قاعدة البيانات**: Supabase PostgreSQL — ملفات الترحيل في `supabase/migrations/`.
- **المصادقة**: Supabase Auth (كلمات المرور تديرها المنصة بالتشفيير — لا تلمسها التطبيق).
- **عمليات إدارة المستخدمين**: تتم عبر دوال خادمية (`api/`) لأنها تحتاج مفتاح الخدمة الذي **لا يصل للمتصفح أبداً**.

## 🚀 خطوات التشغيل الكاملة

> ⏱️ الوقت التقريبي: 20–30 دقيقة. لا تحتاج كتابة أي كود.

### الخطوة 1: إنشاء مشروع Supabase
1. اذهب إلى [supabase.com](https://supabase.com) وأنشئ حساباً ثم **New Project**.
2. اختر اسماً (مثل `daloul-orphans`) وكلمة مرور قوية لقاعدة البيانات واحفظها.
3. انتظر جاهزية المشروع (دقيقة تقريباً).

### الخطوة 2: تطبيق هيكل قاعدة البيانات (مهم جداً)
1. من قائمة المشروع يساراً: **SQL Editor → New query**.
2. افتح ملف [`supabase/database_setup.sql`](supabase/database_setup.sql) من هذا المشروع، **انسخ محتواه كاملاً** والصقه في المحرر ثم **Run**.
3. ستظهر رسالة نجاح — تم إنشاء الجداول والفهارس والقيود والـ Triggers وسياسات RLS.

> بديل لمطوري الأوامر: `supabase link` ثم `supabase db push` باستخدام ملفات `supabase/migrations/`.

### الخطوة 3: ضبط إعدادات المصادقة
من **Authentication → Providers → Email**: يمكنك إبقاء "Confirm email" معطلاً في البداية لتسهيل إنشاء أول حساب (يُنصح بتفعيله لاحقاً).

> من **Authentication → URL Configuration**: أضف رابط موقعك النهائي على Vercel في **Site URL** و **Redirect URLs** حتى تعمل روابط استعادة كلمة المرور.

### الخطوة 4: الحصول على المفاتيح
من **Project Settings → API** انسخ ثلاث قيم:

| القيمة | اسمها هنا |
|---|---|
| Project URL | `VITE_SUPABASE_URL` |
| anon public | `VITE_SUPABASE_ANON_KEY` |
| service_role (سري ⚠️) | `SUPABASE_SERVICE_ROLE_KEY` |

### الخطوة 5: النشر على Vercel
1. ارفع هذا المشروع إلى مستودع GitHub (أو استخدم **Deploy** مباشرة).
2. في [vercel.com](https://vercel.com): **Add New → Project** واختر المستودع.
3. Vercel سيكتشف Vite تلقائياً. **قبل النشر** أضف متغيرات البيئة في
   **Settings → Environment Variables** (القيم الثلاث من الخطوة 4):

   ```
   VITE_SUPABASE_URL = https://xxxx.supabase.co
   VITE_SUPABASE_ANON_KEY = eyJ...
   SUPABASE_SERVICE_ROLE_KEY = eyJ...   ← سرّي، للخادم فقط
   ```
4. اضغط **Deploy** وانتظر اكتمال البناء.

### الخطوة 6: إنشاء حساب المدير الأول (مرة واحدة فقط)
1. افتح رابط موقعك على Vercel.
2. بما أنه لا يوجد أي مدير، ستظهر تلقائياً **شاشة «إنشاء حساب المدير الأول»**.
3. أدخل اسمك وبريدك وكلمة مرور قوية وأنشئ الحساب.
4. من هذه اللحظة **تُغلق شاشة الإعداد تلقائياً للأبد** — وأي تسجيل جديد يدخل النظام يبقى
   **معلقاً حتى تفعّله أنت** من (الإعدادات → إدارة المستخدمين).

### الخطوة 7: إضافة المستخدمين وتوزيع الأدوار
من داخل التطبيق: **إعدادات المدير → إدارة المستخدمين → + إضافة مستخدم**
- اختر الدور: موظف (إضافة وتعديل) أو مشاهد (قراءة فقط) أو مدير.
- إن لم تحدد كلمة مرور ستُولَّد كلمة مؤقتة تظهر لك مرة واحدة لتشاركها مع المستخدم.

### الخطوة 8 (موصى بها): إيقاف التسجيل الذاتي
بعد إنشاء كل الحسابات، من Supabase: **Authentication → Providers → Email** → أوقف
"Allow new users to sign up". حتى مع إبقائه مفتوحاً، أي تسجيل جديد يبقى معلقاً بلا أي صلاحية.

## 🔐 الأمان

- **Row Level Security** مفعلة على جميع الجداول؛ المستخدم المجهول (anon) لا يقرأ ولا يكتب أي شيء.
- **كلمات المرور**: يديرها Supabase Auth بالكامل (bcrypt) — لا يخزن التطبيق أي password/hash/salt.
- **المفتاح السري** (`SUPABASE_SERVICE_ROLE_KEY`) موجود فقط في متغيرات بيئة Vercel الخادمية ولا يُسلَّم للمتصفح أبداً.
- **حماية من تصعيد الصلاحيات**: trigger على مستوى قاعدة البيانات يمنع أي مستخدم من تعديل دوره أو تفعيل نفسه.
- **حماية آخر مدير**: لا يمكن حذف/تعطيل/تخفيض آخر مدير نشط في النظام.
- **سجل نشاط محمي**: لا يمكن لأحد (حتى المدير) تعديل سجل النشاط أو حذفه — للقراءة فقط.
- **XSS**: كل النصوص المعروضة من قاعدة البيانات تُهرَّب قبل العرض.
- **حقن المعادلات**: قيم CSV المصدَّرة تُنقّح ضد `= + - @`.
- **حقن الاستعلامات**: جميع الاستعلامات عبر supabase-js (معاملات آمنة)، ونصوص البحث تُنظف.
- **HTTPS** تلقائي عبر Vercel مع رؤوس أمان إضافية (`X-Content-Type-Options` وغيرها).
- **جلسات**: استعادة تلقائية عند إعادة الفتح + تجديد تلقائي للرمز + رسالة عربية عند انتهاء الجلسة.
- **رسائل خطأ عربية آمنة** لا تكشف تفاصيل تقنية: (تعذر الاتصال بقاعدة البيانات / انتهت جلسة الدخول / ليس لديك صلاحية / هذا السجل موجود بالفعل / لا يمكن حذف الأسرة لوجود أيتام مرتبطين بها).

## 💾 النسخ الاحتياطي الحقيقي

نُميّز بوضوح بين مستويين:

1. **النسخ الاحتياطي الكامل لقاعدة البيانات (Disaster Recovery)** — مسؤولية منصة Supabase
   (نسخ يومية تلقائية على الخطة المجانية، وت timestamp recovery على الخطط المدفوعة).
   لا يوجد داخل التطبيق زر يدّعي ذلك.
2. **تصدير بيانات التطبيق (JSON)** — من صفحة «النسخ الاحتياطي والبيانات»، للمدير فقط،
   لأرشفة البيانات أو نقلها. مكتوب في الواجهة بوضوح أنه ليس نسخة استرداد كارثي.

## 📦 ترحيل بيانات النسخة القديمة

إذا كنت تستخدم النسخة القديمة التي تعمل بالتخزين المحلي (IndexedDB):

1. من **النسخة القديمة**: صفحة النسخ الاحتياطي → **تصدير نسخة احتياطية** (ملف JSON).
2. من **النسخة الجديدة** (بعد نشرها وتسجيل دخول المدير): صفحة «النسخ الاحتياطي والبيانات» →
   **ترحيل بيانات النسخة القديمة** → اختر الملف.
3. النظام يفحص كل سجل، **يتجاهل المكرر** (بنفس رقم الملف)، ينشئ الأسر المرتبطة تلقائياً،
   ويعرض ملخصاً: كم سجلاً استُورد وتخطى وكان غير صالح.
4. كل سجل مستورد يخضع لنفس قيود قاعدة البيانات (جوال فلسطيني، هوية 9 أرقام، تواريخ...).

> لن تُرفع أي بيانات وهمية/تجريبية تلقائياً — الترحيل يدوي وصريح وللمدير فقط.

## 🧪 الاختبارات

```bash
# اختبار قاعدة البيانات وRLS محلياً (يتطلب PostgreSQL مثبتاً + sudo):
npm run test:db
# ينفذ 75 فحصاً: الأدوار، القيود، التكرار، العلاقات، التوقيتات، سجل النشاط، الحماية من التصعيد

# اختبار الواجهة من طرف إلى طرف (متصفح حقيقي + محاكاة خادم Supabase):

# ينفذ 29 فحصاً على الواجهة المبنية: شاشات الدخول والإعداد، لوحة التحكم،
# البحث والترقيم الخادميان، نموذج الخطوات الثماني، منع التكرار، QR،

node tests/e2e-ui-test.mjs

# اختبار أمني شامل على مشروع Supabase الحقيقي:
SUPABASE_URL=... SUPABASE_ANON_KEY=... SUPABASE_SERVICE_ROLE_KEY=... \
ADMIN_EMAIL=... ADMIN_PASSWORD=... \
npm run test:rls

# فحص النشر على Vercel:
BASE_URL=https://your-app.vercel.app node tests/smoke-test.mjs
```

## 🩺 استكشاف الأخطاء

| المشكلة | الحل |
|---|---|
| شاشة «لم يتم إعداد ربط قاعدة البيانات» | أضف `VITE_SUPABASE_URL` و `VITE_SUPABASE_ANON_KEY` في Vercel ثم **Redeploy** |
| «تعذر الاتصال بقاعدة البيانات» | تأكد من صحة الرابط والمفتاح، وأن مشروع Supabase نشط |
| شاشة الإعداد الأولي لا تظهر | يعني أن مديراً موجوداً بالفعل — سجّل الدخول بشكل طبيعي |
| زر إدارة المستخدمين يعطي «إعدادات الخادم غير مكتملة» | أضف `SUPABASE_SERVICE_ROLE_KEY` في متغيرات بيئة Vercel (خادمية) وأعد النشر |
| روابط استعادة كلمة المرور لا تعمل | أضف رابط موقعك في Supabase → Authentication → URL Configuration |
| «لا يمكن حذف الأسرة لوجود أيتام مرتبطين بها» | هذا سلوك مقصود لحماية البيانات — احذف/انقل الأيتام أولاً |
